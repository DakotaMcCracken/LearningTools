Interactive versions of the two take-home models. Each slider re-solves the full equilibrium, so you can see which assumption drives which result.

What the model is doing

Steps 1–6 are the main model (Part A, then Part B). Items tagged extension or robustness are add-ons.

  1. Consumers pick housing.Commute cost depends only on distance x, so a family 5 km out pays the same price per sq ft in either half. Try: raise the preserve cost. The housing price chart has one line and it never splits. Then raise the preserve commute cost: now it does.
  2. Developers pick building height.In the preserve, capital costs more, so developers build shorter (lower S). Less floor space per acre means they can pay less for land.
  3. Land rent sets the edge.Each half ends where land rent falls to agricultural rent rA. The preserve's rent is lower, so its edge comes sooner.
  4. Density follows.Lots are the same size in both halves, but buildings are shorter in the preserve, so fewer people per acre.
  5. Everyone lives somewhere.With a fixed population, utility u adjusts until the two halves together house everyone. Try: raise the population.
  6. Part B: finite preserve.Beyond radius xR the land is unrestricted again, so land rent jumps up there. Try xR ≈ 14.5 for leapfrog development, or 7 for a seam.
  7. Amenity extensionIf living by nature is pleasant, preserve-side housing commands a premium. Past a threshold the city tilts toward the preserve.
  8. Costlier roads robustnessRelaxes Brueckner's equal-commute-cost assumption. If each km through the preserve costs more to travel, the housing price curve splits and the preserve side shrinks further.

The equations behind it
Consumers: v(y − tx − p q, q) = u, v₂/v₁ = p → p(x), q(x) same in both halves Developers: p h'(S_j) = i_j, r_j = p h(S_j) − i_j S_j → S_P < S_U, r_P < r_U Edges: r_j(x̄_j) = r_A Population: π∫₀^x̄U x D_U dx + π∫₀^x̄P x D_P dx = L, D = h(S)/q Road variant: preserve-side commute = t_P·x inside the preserve (+ t_U beyond x_R) → ∂p_P/∂x = −t_P/q, so p_P(x) < p_U(x) Forms used: v = c^0.75 q^0.25, h(S) = S^0.75, y = 1, r_A = 0.01

What the model is doing

Steps 1–6 are the main model (Part A, then Part B with a money cost). Items tagged robustness or alternative scenario are add-ons.

  1. Who can do which job.Robots: Gotham only, high-human-capital (HHC) workers only. McDonald's: both cities, anyone, equally productive.
  2. Labor demand sets wages.The robot wage falls as more people build robots. The McDonald's wage rises with local residents (everyone eats there) and falls with more McDonald's workers.
  3. Housing sets rents.Rent rises with the number of residents in a city.
  4. Low-skill (LHC) workers are indifferent between cities.Wage minus rent must be equal in Gotham and Styx, so McDonald's wage gap = rent gap. Watch the two gap numbers match.
  5. HHC workers pick the better job.If robots pay more than Gotham McDonald's, every HHC builds robots (separating). If there are too many HHC, the robot wage falls to the McDonald's wage and some HHC flip burgers (pooling). Try: slide Lh past ~2.9.
  6. Part B: teleportation.Living in Styx while working in Gotham saves the rent gap and costs c. Both types gain the same amount, so whoever has the lower cost goes first. Once people teleport, rent gap = wage gap = c. Try: lower c below ~0.15.
  7. Time cost of teleporting robustnessIf teleporting costs a share of your wage instead of a fixed fee, low-wage workers teleport first and high-wage workers never do.
  8. Expensive Styx alternative scenarioMake Styx's housing scarce and the McDonald's wage ranking flips: Styx McDonald's pays more.
